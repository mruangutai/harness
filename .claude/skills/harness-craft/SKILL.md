# Craft — the principles, by seat

Each principle below is a leaf under `<HARNESS_CONTROL_PLANE_ROOT>/.agents/skills/harness-craft/references/`.
The line here is the trigger; the leaf is the rule. Each line names the seats it binds. **Read the
leaf in full before applying it**, and read only the leaves tagged with your seat unless a dispatch
names another.

## Citing a principle

In your artifact, under a heading `## Principles applied`, name each principle that shaped a
decision and the specific choice it changed — one line per principle. Cite only a leaf you read
this run. A citation the reviewer cannot check is decoration: **Build the Lever** counts only when
the diff carries the script, codemod or generator; a test kept under **Test Behavior** counts only
when it would fail if every function it imports returned nothing (`harness-code-review` § Absence,
subject and mutant). The heading is part of the artifact, never a digest key.

The five constitution rules every seat already carries — verification is the product, never
falsify the record, no more specific than necessary, you may refuse, hand off while sharp — are
`harness-principles`, not repeated here.

- **Attack the Premise** (`references/attack-the-premise.md`) — `dev`, `eng-lead`, `pm`. Apply when two or more fixes that share one premise have failed the same gate.
- **Build the Lever** (`references/build-the-lever.md`) — `dev`, `qa`. Apply to any non-trivial work, not just bulk work: edits, migrations, analyses, checks.
- **Delete First** (`references/delete-first.md`) — `dev`, `eng-lead`, `code-reviewer`. Apply when refactoring, sequencing an addition or rewrite, judging diff size, or tempted to add a layer, abstraction, or threaded signal.
- **Experience First** (`references/experience-first.md`) — `eng-lead`, `pm`. Apply when product, UX, or feature-scope tradeoffs come up.
- **Foundational Thinking** (`references/foundational-thinking.md`) — `dev`, `eng-lead`. Apply before writing logic: choosing core types and data structures, sequencing scaffold against feature work, or asking what concurrent actors share.
- **Make Operations Idempotent** (`references/make-operations-idempotent.md`) — `dev`, `eng-lead`. Apply when designing commands, lifecycle steps, or processing loops that run amid crashes, restarts, and retries.
- **Migrate Callers, Then Delete Legacy APIs** (`references/migrate-callers-then-delete.md`) — `dev`, `code-reviewer`. Apply when introducing a new internal API while old callers still exist.
- **Model the Domain** (`references/model-the-domain.md`) — `dev`, `eng-lead`, `code-reviewer`. Apply when writing stateful logic, or when code branches a lot or repeats a shape assumption across files.
- **Outcome-Oriented Execution** (`references/outcome-oriented-execution.md`) — `dev`, `eng-lead`, `pm`. Apply during planned rewrites and migrations with explicit phase boundaries.
- **Redesign From First Principles** (`references/redesign-from-first-principles.md`) — `dev`, `eng-lead`, `pm`. Apply when integrating a new requirement into an existing design.
- **Separate Before Serializing Shared State** (`references/separate-before-serializing-shared-state.md`) — `dev`, `eng-lead`. Apply when concurrent actors might write to the same file, branch, key, or state object.
- **Type System Discipline** (`references/type-system-discipline.md`) — `dev`, `code-reviewer`. Apply when designing types, reviewing a function signature, or writing code in any statically typed language.
