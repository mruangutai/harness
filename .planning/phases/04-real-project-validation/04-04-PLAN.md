<objective>
Run the full harness on Sub-Phase C of the Implentio PDF editor — post-annotation re-parse, re-score, and data unblock.

Purpose: Sub-Phase C closes the routing loop started in Sub-Phase A. After a support team member submits annotations (Sub-Phase B), the system must re-parse the PDF using the corrected fields, re-score confidence, and unblock data entry when the score reaches ≥90%. This sub-phase has explicit state machine behavior (blocked → annotated → re-parsing → unblocked) and an unblock API contract, making it a strong architectural phase — the pre-discuss trigger applies.

Output: Evidence artifacts proving harness constraints were active. Sub-Phase C is also the completion proof for VAL-01: the full PDF editor feature (500+ LOC across 3 sub-phases) has been built end-to-end using the harness.

EXECUTOR NOTE: YOU ARE THE HUMAN (the CTO). Initiate each step. Claude agents assist at each stage.
</objective>

**Key questions to expect from the reviewer:**
- What triggers the re-parse? (annotation form submission, explicit trigger button, or automatic?)
- Is re-parse synchronous or async? (blocking request or background job?)
- What is the status state machine? (blocked → annotated → re-parsing → unblocked? Or fewer states?)
- What happens if re-parse produces score < 90% again? (re-enter queue, or different handling?)
- Is there a maximum retry count to prevent infinite re-parse loops?
- What is the unblock API contract — who calls it, what validates the ≥90% condition?

### Stage 2: Discuss Phase

**Command:** `/gsd-discuss-phase [sub-phase-C-number]`

**What to decide during discuss:**
- Re-parse trigger: automatic on annotation submit, or manual "re-parse" button?
- Async vs sync: background job (queue-based) or synchronous re-parse inline?
- Status state machine: define all states and valid transitions explicitly
- Below-threshold re-try: what happens if confidence is still < 90% after re-parse?
- Unblock contract: which service/endpoint performs the unblock? How is ≥90% verified?
- Idempotency: what if annotation is submitted twice or re-parse fires twice?

**Scope creep to catch:** Any multi-tenant features, notification emails to support team, or dashboard analytics — push to future phases. Sub-Phase C scope is strictly: re-parse → re-score → unblock.
