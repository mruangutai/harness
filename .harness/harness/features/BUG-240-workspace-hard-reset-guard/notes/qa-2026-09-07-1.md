## 6. Material gap: no case exercises the guard against a REAL git checkout for ORDERING

Every one of the eight BUG-240 cases that asserts *ordering* (case 1, case 5, the (B)-block
addition) does so via `Recorder`, a `run_git` stand-in — never real git. The three cases that DO
use real git (2, 3, 4) never assert ordering; they assert end states (message content, byte
survival, final branch). This is a genuine, if narrow, gap:

**Concrete failure scenario that ships green:** suppose a future edit changes the *dirty check's*
git invocation from `run_git(["status", "--porcelain"], path)` to something that internally
shells out via a DIFFERENT code path not routed through the module's `run_git` (e.g. a direct
`subprocess.run` call bypassing the `FACTORY_GIT` env-var indirection documented in the
docstring). Every Recorder-based case (1, 5, the (B) check) would still pass, because they only
ever observe calls that arrive through the patched `fw.run_git` — a call issued through a
different subprocess invocation is simply invisible to `Recorder.calls`, so `kinds` would still
correctly show no `fetch`/`reset`/`clone` even though the *implementation* had silently forked its
git access into an untested seam. Meanwhile none of the real-git cases (2/3/4) assert ordering, so
they would not catch this either — they only prove the eventual state (file survives, ignored dirt
untouched), not that the destructive command was never attempted before the refusal in the FIRST
place, against real git's actual timing/side-effects. This is a narrow gap: it requires a
specifically adversarial refactor (bypassing `run_git`'s own indirection, which the module
docstring says exists precisely so tests CAN substitute a recorder), not a plausible innocent
regression under this file's current shape — the day-to-day risk (an accidental reordering within
`_main`) is caught by both the Recorder-based ordering cases AND, for the non-guard refresh
order specifically, the (B)-block real-recorder check. I am flagging this as a finding, not
inventing a test for it (out of scope for a gate dispatch) and not silently passing over it.
