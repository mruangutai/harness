# Send-back criteria — distill-product (written before dispatch)

Applies to distill-pm and distill-code-reviewer. Send back once only if any fails:
1. Every applied op is reflected in the receipt and the resulting file (entry id + distinctive token).
2. Entries are WHEN/DO, <=50 words, no FEAT/T-/#NN ids.
3. Layer: a repository-tier entry turns on a harness-specific path/script/invariant; craft entries are not repo-specific.
4. At-cap sections: each add displaces a named survivor (replace, or drop+add); no count exceeds its cap; repository file <=40 lines.
5. Each relayed candidate is accepted or rejected WITH a reason in the member's digest.
6. Gate fields use the distill did-nothing spelling (code-reviewer: code_grade n_a, reviewed none).

Not send-back grounds: a displacement or rejection I would have judged differently (O-03).
A refusal of the code-reviewer dispatch by dispatch-guard is not a member failure: it is reported verbatim, never worked around by relabeling the mission.
