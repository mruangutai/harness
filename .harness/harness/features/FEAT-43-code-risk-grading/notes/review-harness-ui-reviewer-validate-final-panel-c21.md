## Scepticism point 4 — duplicated binding error: CONFIRMED, ranked low

Reproduced live: wrote a probe digest (`/tmp/feat43_probe_digest.md`, outside the repo) with
`artifact: none`, `code_grade: n_a`, and a well-formed `reviewed:` range, then ran
`validate-digest.py harness-code-reviewer /tmp/feat43_probe_digest.md`:

```
VERDICT: BLOCKED (contract violation)
  - code_grade cannot be bound to review_sha: artifact 'none' does not name a .harness/<repo>/features/<FEAT>/ location — write your review under that feature's notes/.
  - code_grade cannot be bound to review_sha: artifact 'none' does not name a .harness/<repo>/features/<FEAT>/ location — write your review under that feature's notes/.
```
exit 1, the identical line printed twice. Root cause read in source: `_resolve_feature_dir`
(validate-digest.py:714) is called once directly inside `code_grade_bound_to_review`
(validate-digest.py:882, the SEC-01 unconditional check at line 1132) and a second time inside
`resolve_review_sha` (validate-digest.py:843), which the `code_grade == "n_a"` branch calls again at
line 1146 whenever `reviewed`'s shape is valid — two call paths converging on the same producing
site with no de-duplication of the `err` list.

**Severity: low.** It does not change the decision — the digest is correctly refused either way —
and the two lines are byte-identical, not contradictory, so a human reading the output is not misled
about *what* is wrong, only momentarily made to wonder whether there are two separate problems.
Worth fixing (de-dupe `err` or short-circuit the second call), not worth blocking this panel on.
