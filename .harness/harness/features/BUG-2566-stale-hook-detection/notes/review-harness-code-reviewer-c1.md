## Findings

1. **Substance · high · T-01 · D-02 mismatch — no content fingerprint can count as a match** (`.omp/extensions/harness-hooks.ts:78–81,89–105,1799–1816`). If a checkout update removes the file after OMP reads its source but before the module initializer reads the path again, the loaded baseline is `absent`. If the file is still gone on Main's next `task`, current state is also `absent`. The equality check returns no refusal and dispatch proceeds through the old code without a restart instruction. Identical `unreadable` states have the same defect. Keep recording the states allowed by D-03, but require a verified load-time content hash before declaring freshness. Otherwise return the one-line restart refusal on governed calls, retaining the existing BLOCKED-yield and Main recovery exceptions. Add a missing-baseline regression witness.
2. **Substance · med · T-01 · SC-01 omission — the FIFO fixture does not verify that it made a FIFO** (`tests/unit/omp-hooks.test.ts:4506–4520`). If `mkfifo` is unavailable or fails, the child ignores its result after unlinking the hook. The detector reports the deleted-file case, the child exits normally, and every FIFO assertion passes. Even a detector that hangs on a FIFO would go green in that fixture state. Require successful `mkfifo` and verify the resulting kind before invoking the detector in the bounded child. Also assert the filename in its relative-path position: `expectStale` currently accepts an absolute path ending in the same suffix (`:4468–4472`).
