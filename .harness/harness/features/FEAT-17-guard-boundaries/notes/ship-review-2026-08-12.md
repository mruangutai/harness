# FEAT-17 — guard boundaries — ship review

Closes the two issues it was planned against: **#261** (the two write surfaces diverged) and **#103**
(a worktree outside `.claude/worktrees/` is silently ungoverned).

## What breaks today, and what stops breaking

**#261, measured at `a29ad06`:** with `src/**` granted to `harness-backend-dev`, a Write to
`<root>/src/main.py` exited 2 while `echo hi > <root>/src/main.py` exited 0. An agent refused by one
guard could make the identical write through the other. This hook exists *because* an agent routed
around the other one, so a divergence between them is a bypass by construction.

**#103:** a linked git worktree living outside `.claude/worktrees/` silently disables the harness
machinery for every session opened in it. Three writes that exit 2 in the real checkout exited 0 when
written into a sibling worktree.

After this change there is **one boundary rule**, in `harness_boundary.py`, imported by both guards.
A checkout in the wrong place cannot be created, cannot be written into, and cannot host a governed
session.

## The change

| File | What |
|---|---|
| `harness_boundary.py` | **new.** The boundary rule, moved verbatim out of `check-domain.sh`'s embedded Python — which is why `bash-write-guard.sh` could not consult it. A heredoc cannot be imported |

| `DECISIONS.md` | DEC-193, plus amendment 1 |

Six of seven tasks were `main-session-direct` under the **DEC-174 carve-out** — direct edits, tests
run explicitly, a human reading the diff — because green gates cannot vouch for the code that
produces them. T-07 ran through the product lead to `harness-documentor`.

## What the review panel found, and it was right

The panel returned a **`high`**: the fix had reinstalled #103's own failure direction inside #103's
fix. Verified at source and reproduced end to end before anything was touched.

- **F-A [HIGH].** `worktree_owner()` returned `None` on every parse failure and every caller read
  `None` as *not a worktree*, so the write was **allowed with no stderr**. Appending one `\xff` byte
  to an otherwise valid `.git` pointer turned the identical write from exit 2 into a silent exit 0.
  Fixed with a third return state callers refuse rather than ignore, plus `MULTILINE` on the pointer
  regex — `$` had anchored at end-of-string, so any second line failed the whole match.
- **F-B [med].** `check-state.sh` absorbed the `ImportError`, skipped every INV-25 branch, and
  printed *"all state invariants hold"* while exiting 0. The fourth import route, and the only one
  that did not fail closed. Now a violation.
- **F-C [med, record].** DEC-193's claim of preserved Bash-route behaviour was too wide by one
  column. Amended with the measured table rather than left standing.

Nine new cases, every forbidden one paired with an allow. Mutation-proved: reverting F-A reddens four
Write cases and three Bash cases; reverting F-B reddens u.7.

## Evidence

**One implementation, proved by mutation rather than by grep.** A grep shows the literal appears
once; it cannot show both guards *read* that copy. An isolated `bin/` holding all four files, one
pinned payload, `WORKTREES_SEGMENT` changed **by name** in the copied module: both routes flip 0 → 2.
A flip on one route only would mean a second copy survives, and the case says so.

**Gates at HEAD.** `run-unit-tests.sh` exit 0 on three consecutive runs; `check-state.sh` 0;
`check-plan-routes.py` 0 violations across 8 plans; `test-gen-decisions-index.py` 0 with the index
regenerated byte-identically. The qa gate returned PASS at `c6a28bd` with `matrix_ok: true`.

**Ten of ten success criteria.** SC-07 was found `not_met` by the goal-check — a missing test, not a
broken guard — and closed with one case per route. SC-09 was **amended by the operator**, visibly,
with the original struck beneath it: it named two capture files that were never created and could
not be, because the removal happened outside T-06 during the FEAT-13 close-out. `git log --all`
confirms neither file ever existed on any branch. Nothing was manufactured.

## What this does not close, stated rather than left to be found

- **Three divergences between the two write routes survive deliberately**, and DEC-193 records all
  three. REQ-05 commits to one shared *implementation*, not to identical verdicts.
- **The target-side branch is not mutation-proved.** The mutation proof pins the session root inside
  the worktree, so it is direct evidence for the **root-side** check only. The target-side branch is
  covered by behavioural cases on both routes. Neither half may be widened into the other.
- **The worktree-creation scan was never tested against evasion** — `sh -c`, `command git`, an alias,
  `xargs`. It is REQ-03's only mechanism.
- **`classify`'s `shared` outcome is unreachable**, so the branch handling it in
  `bash-write-guard.sh` is dead code new in this diff.
- **One unreproduced gate failure.** `run-unit-tests.sh` exited 1 once during this session and
  returned 0 on the three runs after it. No cause found. Recorded because an unexplained failure in
  a gate is worth knowing about.
- **`--kind unit` runs neither guard suite nor `test-check-state.py`**, despite all three matching
  the unit detect glob. Backlog, not a defect of this change.
