What was built

Four defects in how the harness records and locates a run's own artifacts, closed as one feature:

  1. #1056 — validate-digest.py could not tell a present-and-empty last_assistant_message from an absent one, so an agent that returned nothing passed the gate. Now exit 2 for empty, exit 0 with a stated reason for absent/null.
  2. #1057 — a governed agent could write a feature artifact into the main checkout while its feature had a registered worktree. Now bound on both write routes: the PreToolUse Write route (check-domain.sh) and the Bash route (bash-write-guard.sh), each naming the target and the checkout the write belonged in.
  3. #1058 — a Write to an existing runs/<runid>/digest.md could destroy the recorded digest. Now refused unless the payload carries the existing text as a prefix; an unreadable file is treated as "recorded", not as "absent".
  4. (operator-authorized, no issue) — a lead's digest was resolved against the owner root rather than the checkout the lead ran in, so DEC-156 could not see a contract-violating digest written inside a worktree. Now resolved through inflight_registry.feature_root.

Supporting seam: harness_boundary.worktree_for_feature selects a feature's worktree by prefix and raises AmbiguousWorktree on two candidates; inflight_registry.feature_root was cut over to it with its signature, return type and total-fallback contract intact.

The rules are on the permanent record as one decision in .harness/harness/docs/DECISIONS.md ("A run's own record is enforced…"), with DECISIONS-INDEX.md regenerated byte-identical.
