## Q2 — corpus-root derivation: `harness_boundary.py`, beside `worktree_owner()`

**Decision:** (a), not (b) a new module. **Rejected alternative:** a standalone `corpus.py`/similar.

**Why:** `git grep -l 'import harness_boundary\|from harness_boundary'` (excluding `tests/`) returns **28 files**, including 6 of the corpus-relevant readers themselves: `board_lifecycle.py`, `check-plan-routes.py`, `check-state.sh`, `feature-worktree.py`, `quarantine.py`, `validate-feature-json.py`. A new module gains these six readers **zero** import-cost saving (they already pay the `harness_boundary` import) and would itself have to import `harness_boundary` to call `worktree_owner()`/`resolve_root()` — the design's own proposed body, `corpus_root() = worktree_owner(cwd).owner_root or resolve_root(bin_dir)`, is a three-line wrapper over two functions that already live there. Deletion test: delete `corpus_root()` and the six readers still compile and import cleanly against `harness_boundary` — nothing else in the module depends on it. Two-adapter test: there is exactly **one** call convention (delegate straight through to the two existing functions); a separate module would be a pass-through layer with no second implementation or second calling convention to justify the boundary — the "one adapter = hypothetical seam" case.

**Resolved public surface** (design proposed 5 names):

| Name | Verdict | Named caller(s) | Failure/refusal mode | Lifetime |
|---|---|---|---|---|
| `corpus_root(cwd)` | **EARNED** | all 6 corpus sweeps above + `merge-gate.py`, `check-domain.sh` (newly found) | returns `None` when `worktree_owner()` returns no owner root **and** `resolve_root()` fails; caller refuses, never falls back to `cwd` | none held — pure function, no cache, called once per process |
| `corpus_features(root)` | **EARNED** | same 8 callers, replacing their private `glob.glob(...,"*","features","*",...)` | resolves the set from `git ls-tree -d <ref>:.harness/*/features` (design's own text); a git failure (non-repo, detached, corrupt) is a refusal, not an empty set | none — recomputed per call; no process-lifetime cache proposed or needed at these call volumes (≤ once per CLI invocation) |
| `corpus_read(path, ref)` | **EARNED, but only if the refactor actually lands** | `check-state.sh`, `board_lifecycle.py`, `check-plan-routes.py`, `validate-feature-json.py`, `merge-gate.py` — all currently read materialised content with `open()`/`read()`; this is the function that replaces those calls when the corpus is not on disk | a ref that does not resolve, or a path `git show` reports absent at that ref, is `None`, not an exception swallowed to `""` — callers must treat `None` distinctly from "empty file" | none |
| `materialised_count()` | **CUT** | no named caller wants a bare count; every caller wants a refuse-or-continue decision | — | — |
| `refuse_if_incomplete()` | **EARNED, but relocate into `corpus_features()` itself** — see Q5a | same 8 callers | prints `N of M features materialised` + corpus root, exits non-zero | none |

`materialised_count()` is cut: folding its arithmetic into `refuse_if_incomplete()` (or into `corpus_features()`, see Q5a) removes a name nothing calls independently — no more specific than necessary.

## Q3 — declaring provider + ref for a corpus-needing task

**Decision:** a `corpus:` block on the plan task (`plan.yaml`, sibling to the existing `verify:` field — same authoring seam, same file, same audience: pm/eng-lead at plan time), e.g. `corpus: {provider: history|path, ref: <resolved-sha-or-branch>}`. **Enforcing instrument:** `dispatch-guard.sh`, the same script DEC-214 already made refuse a dispatch missing `HARNESS-FEATURE-TREE-ROOT` at exit 2. Extend it: when the dispatched task's plan entry carries a `corpus:` block, the dispatch text must carry a matching `HARNESS-CORPUS-PROVIDER`/`HARNESS-CORPUS-REF` line, or `dispatch-guard.sh` refuses at exit 2, naming the missing line — mechanically identical to the existing feature-tree-root refusal, not a new enforcement shape.

**Rejected alternative:** a bare argument to the corpus API (`corpus_read(path, ref)` etc.) with no upstream declaration. Rejected because "the mechanism is unspecified" in the grilling artifact is exactly the gap between *code accepting a ref* and *someone being required to state one before dispatch* — an argument with a default is satisfiable silently; only a dispatch-guard-enforced line has no default to fall back on.

**Failure mode of my own mechanism, stated honestly:** the `corpus:` declaration is checked for **presence**, never for **correspondence** — nothing confirms the dispatched agent's code actually calls `corpus_read`/`corpus_features` with the declared provider/ref rather than a stale `glob.glob(...)`/`open()` call left over from before this refactor. A task can carry a perfectly-formed `corpus: {provider: history, ref: main}` line, pass `dispatch-guard.sh` cleanly, and still execute code that reads the working tree relative to `cwd` — reproducing the exact fail-open this effort exists to close, now hidden behind a green declaration instead of no declaration at all. This is a real residual gap, not fully closable at the dispatch-guard layer (it would need a code-level check — e.g. a grep-based guard, in the `suite_layout.py` self-policing style, that a task's diff contains no raw `features/*` glob outside `harness_boundary.py` itself). I am not proposing that guard here — it is plan-build-phase work, out of scope for this research pass — but it is the honest cost of the mechanism as ruled.

## Q5a — read-path design assessment

**Three-anchor extension of DEC-214: does NOT survive as framed, and should not be built that way.** DEC-214 governs *instruction-path text* — placeholders an agent types into prose/dispatch, mechanically checked by `check-instruction-paths.py` over inline spans and fenced code blocks (DECISIONS.md L6773-6776). `corpus_root()` is a plain function call inside Python source, never written by an agent as prose it composes — no agent is instructed to type `<HARNESS_CORPUS_ROOT>` into a dispatch. Calling it a "third anchor" implies it needs the same injection/placeholder/static-check machinery the other two anchors have; it does not, and building that machinery would be pure ceremony. **Ruling: build `corpus_root()` as an ordinary `harness_boundary.py` function (Q2), not as a DEC-214 amendment; the "three anchors" framing is decorative and should be dropped from the plan's language.**

**Two providers: both survive, but the design's ranking ("history authoritative, path convenience") is not uniformly true.** `check-domain.sh:_hardlink_plan` (a corpus sweep this research found, missing from the design's own ledger) resolves hardlink identity by `(st_ino, st_dev)` — a git-history read can never supply an inode number, so for *this* real caller the path provider is not a "convenience fallback," it is the *only* correct source. Both providers are earned by distinct, named, existing callers; the design should state the split as "content reads: history-first; identity/inode reads: path-only," not as a strict authority ranking.

**Fail-closed contract: makes the *known* sweeps fail-closed, does not make the *class* of defect impossible.** As designed, `refuse_if_incomplete()` is a second function each corpus-sweep callsite must remember to call after `corpus_features()`. This research just found two corpus sweeps (`merge-gate.py`, `check-domain.sh`) that neither the ticket's 11 nor the design's 12-item ledger named — proof by construction that "enumerate every corpus sweep and edit each one to call the refusal" is not a closed set; a fifteenth reader added next quarter reopens the exact fail-open (`check-state.sh` swept 1 of 88, exited 0) this effort exists to close, silently, because nothing forces the new reader through the refusal path. **This part of the design should not be built as two separable public functions.** `corpus_features()` should perform the completeness check internally and refuse non-optionally on every call — making `corpus_features()` the only sanctioned corpus-enumeration entry point in the codebase is what turns "fixed for the sweeps we found" into "structurally impossible for any caller," which is the actual bar the bedrock rule sets.
