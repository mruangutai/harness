# FEAT-53 abandoned — operator ruling, 2026-09-22

## Why
After five fix-to-green rounds the automated UI lane reports 23/23, yet the built dashboard (runs/2026-09-22-t32-round5-eng/ui/evidence) does not resemble the approved prototype (notes/prototypes/FEAT-53/observed-1440.png; live prototype side-by-side confirmed by the operator). Two root causes, both structural:
1. The prototype was never the implementation's source: the client was written from DESIGN prose (T-10..T-20) while the approved composition lived in a separate Astryx app under notes/prototypes/. The lane automated only measurable clauses (geometry numbers, token ownership, contrast, tab order, axe); fidelity stayed an inspection row and pixel baselines were opt-in and never enabled, so a page can be green and wrong.
2. Against the real fleet the collectors return mostly nulls (ship records only since instrumentation on 2026-09-17 and written only by gh-sync ship; run timestamps on 13 of 93 features; the work enumeration includes stale worktree-resident dirs and station-less grilling/worktree rows), and the UI renders nulls verbosely — 172 items, 17 errors, 0 measured features; table and Kanban unusable.

## Ruling
Start over from the prototype as the source. A new feature branches from feat/FEAT-53 and, in its first commit, deletes the client (`bin/dashboard/client/`), the dashboard backend (`bin/dashboard/*.py`, fixtures) and the FEAT-53 e2e lane; it keeps `ui_contract.py`, the `ui` test kind and the evidence-driven ui-reviewer rule as generic harness tooling (FEAT-1821's enforcement-layer pieces still land). FEAT-53's record is kept; `gh-sync.py abandon` runs from the main checkout when this branch lands (worktree-resident feature dirs are refused, same as FEAT-1821's ship).
