What actually changed

tests/unit/test-factory-claim.py builds two fixture feature trees that carry the same feature id under two different repository segments — kaya-ai and harness. Case 5b polls both and proves neither repository is served the other's data.

Before: both trees carried an empty factory.issues map, so the harness candidate's issue map was never consulted at all. The code was correct; nothing could see it. A mutant that re-keyed the issue-map cache on feature alone — throwing away the repository — broke nothing.

After: each tree carries its own, non-empty, different issue map, and the harness tree's task now depends on a blocker that only its own map can resolve. Now the same mutant breaks case 5b.
