# Security review c4 — BUG-2565

**FAIL — both named F-2 cases now refuse, but the generator still silently removes non-generated YAML and can change its value's type.** Reviewed `104252db..dca6017d59edf5222bbd41de08d2a8a2a0f74c51`, focusing on `b9c98761..dca6017d`. Probes ran only against pinned blobs in scratch directories, not through live enforcement.

## Findings

1. **Substance · med · must fix · T-03 / SC-07** — `.claude/skills/harness/bin/gen-agent-output.py:87–96,107–129`. In a copied agent definition, a non-generated nested flow mapping inherited `output: false` from a YAML merge and explicitly overrode it with a column-zero `output: 0,` line. The generator mistook that line for the root `output`, deleted it, returned 0, and its next `--check` returned 0. The strict reader measured the nested value changing from `int(0)` to `bool(False)`; Python mapping equality treats them as equal. With an inherited integer zero and explicit `!!int 0` override, it also silently removed the override while the parsed value stayed equal, making the value follow later edits to the merge source. Both also occurred at `b9c98761`: this is an unclosed part of the integrity defect, not a c4 regression. The actor needs edit access to the agent definition and a maintainer to regenerate it; no privilege gain or shipped agent using this shape was demonstrated. Select replacement spans by YAML root-key position, or refuse when those spans cannot be verified; add a witness for nested overrides. Type-strict comparison alone catches the first case, not the second.
2. **Substance · low · T-03** — `.claude/skills/harness/bin/gen-agent-output.py:127,140–168`. A self-referential alias in a non-generated field now raises `RecursionError` at the comparison (exit 1 with traceback, all 16 files byte-identical); `b9c98761` accepted it. This is a local generation denial, not a write bypass, but the expected refusal diagnostic is lost.

## Probe results and boundaries

- **Preflight integrity:** Bare and escaped description lookalikes both exit 2 with the value-change reason and all 16 files byte-identical, including an earlier stale persona. Removing only the guard in a scratch copy (M2) makes both exit 0 and delete the line. Malformed YAML, unknown tags, duplicate keys (including a duplicate escaped generated key), and an alias to a removed generated anchor also exit 2 with all bytes unchanged. Invalid UTF-8 exits 1 before writing, unchanged from c3. Ordinary safe tags, aliases and merges outside generated spans survived the probes.
- **Local stderr disclosure:** The value-change refusal does not echo the value. With PyYAML 6.0.3's pure-Python loader, malformed YAML can echo a source-line snippet and duplicate errors include the key; synthetic markers reached stderr both at c3 and c4 (`artifact_accessors.py:421–437`, `harness_yaml.py:43–46,82–99`). c4 appends a fixed suffix. This reaches the invoking maintainer; no new log/export sink or cross-user disclosure was found.
- **Write-phase advisory unchanged:** A second-write `OSError` left the first file updated at both pins (`gen-agent-output.py:171–178`); preflight refusal writes nothing, but subsequent writes are not transactional.
- **Scope:** The full range touches child-to-parent integrity (T-02 yield refusal, DEC-237), schema reference resolution (T-03), and native schema/port drift checks (T-04). The hook still normalizes each dispatch for `dispatch-guard.py` and refuses unavailable validation; the projection confines references to its local schema directory. No new auth grant, credential handling, shell interpolation, network path, or data export was found in the c4 delta. Generated definitions/config are the schema delivery surface; the docs, test/classification edits and feature records introduce no separate runtime input boundary.

**Open questions:** none for this lens.
