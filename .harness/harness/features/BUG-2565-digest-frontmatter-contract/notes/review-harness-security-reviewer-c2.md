## Findings

- **Substance · med · must fix · T-03** — `.claude/skills/harness/bin/gen-agent-output.py:50–63,75–83`. A maintainer regenerating stale `output` can lose an unrelated valid YAML key: a plain `-note: keep` sibling immediately after the output value is treated as a sequence item and deleted. Pinned in-memory rendering loses the key; `bb401aae` preserves it. The result still parses and the regenerated output equals the bundle, so those checks cannot detect the loss. The same scanner still orphans indentationless sequence items after a blank line and duplicates a YAML-escaped spelling of `structured` (both also fail at `bb401aae`). The strict port reader rejects invalid/duplicate YAML, not silent loss of an unrelated key. **Repair:** use YAML token/node spans to identify the decoded generated keys and their complete values; preserve all other bytes and refuse unsafe rewrites before writing. Add parsed-key and byte-preservation witnesses for the three shapes. This requires control of agent frontmatter and a maintainer regeneration, not merely sending a task or editing a schema literal.
- **Substance · low · T-02 · open advisory from c1** — `.omp/extensions/harness-hooks.ts:398–404,432–435,880–885`. Spawn errors can still put the absolute executable path in the child-visible diagnostic; stderr or exception details can also reach the child. The base exposed the detail in passive context; no new credential exposure was observed. **Repair:** return a stable, minimal failure class to the child; put bounded, redacted detail in operator diagnostics.
