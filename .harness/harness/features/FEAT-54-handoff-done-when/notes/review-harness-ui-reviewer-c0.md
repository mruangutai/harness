## Finding

### F-01 — HIGH — a blank `Scope:` is accepted

- **Failure scenario:** an author writes a five-section note containing `Scope:` (or `Scope:   `) and one resolving `Authority:`. The helper strips the line, counts it as the required single scope, and returns no problem; `check-domain.sh` therefore allows the write. The successor receives no label for the immediate action, defeating the completion boundary this feature exists to supply. INV-17 also regards the persisted block as clean.
- **Actual:** `handoff_done_when.py:111-116` strips nonblank lines, selects every line beginning `Scope:`, and validates only that the count is one. It never requires content after the colon. Both enforcement surfaces delegate to that result (`check-domain.sh:1562-1567`; `check-state.sh:1244-1251`). The unit and write-gate malformed matrices cover zero and two scope lines but not an empty value (`tests/unit/test-handoff-done-when.py:56-61`; `tests/integration/test-check-domain.py:4033-4040`).
- **Specified:** REQ-02 requires the line to carry a concise action label (`BRIEF.md:26-27`), and the template requires a concise label for the one action in Next (`templates/HANDOFF.md:39`).
- **Severity:** high — a valid-looking write can omit the core user-facing completion boundary without any warning.
- **Owner lane:** **Main direct mutation (DEC-174 enforcement layer)** for `handoff_done_when.py` and its gate tests. Reject an empty/whitespace-only scope value with an actionable message and add unit plus write-gate coverage.
