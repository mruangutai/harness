## R-1 — pinned blob read: `code_grade._git_show` (T-01 intent, "Read the blob with git -C CODE_ROOT show FULL_SHA:.harness/harness.json")
- Summary: the intent prescribes a new `git show` subprocess. `code_grade.py` `_git_show(repo_root, ref, path)` already does exactly this and, unlike a bare `git show`, separates "path absent at ref" (returns None) from "git cannot answer" (raises RuntimeError) via `_tree_has_path`. validate-digest.py already imports from code_grade (`classify, commit_oid, gated_set`).
- Cost: a second hand-rolled `git show` re-decides absent-vs-unreadable, which T-01 needs as two distinct named refusals ("unreadable blob" vs "missing pinned config"). A bare call collapses both to one non-zero exit; two spellings of the same git read drift.
- Note: `_git_show` is underscore-private and text=True; promoting it (or importing it) is a one-line move. `_git_line_or_none` in validate-digest.py is NOT a fit (swallows stderr, strips, 5s timeout).
- Disposition: fold-in (name `code_grade._git_show` as the blob reader in T-01 intent; map None -> missing-config refusal, RuntimeError -> unreadable-blob refusal).

## R-2 — pin resolution and agreement: `_read_review_sha` / `resolve_reviewed_commit` / `_pins_agree` / `_review_binding` (T-01 intent, "Resolve feature.json review_sha ... A trusted dispatch review_pin may supply an otherwise absent pin ... if both exist they must resolve to the identical product commit")
- Summary: the recorded-pin-else-dispatch-pin-must-agree rule is already implemented in validate-digest.py: `_read_review_sha(feature_dir)` (placeholder vocabulary via `harness_yaml.PLACEHOLDER_UNSET`), `resolve_reviewed_commit(root, rev)` (option-like revision refused via `commit_oid`), `_pins_agree(root, recorded, pinned)` (takes root as a parameter), and `_review_binding` (the #1677 convention the intent itself cites). - Cost: a QA-specific reconciliation re-spells #1677 with different error text and different placeholder handling; the two will diverge on edge cases (`none`/placeholder pin, option-like pin, short vs full SHA).
- Note: for the unbound Harness case `_review_binding`'s own root equals the code root, so its result is directly reusable; only the bound-product case needs `_pins_agree(code_root, ...)` and `resolve_reviewed_commit(code_root, ...)`. `_review_binding` hardwires the root and its messages begin "code_grade cannot be bound" — a root parameter or a QA-prefixed wrapper is the reuse cost, not a rewrite.
- Disposition: fold-in (T-01 intent: build on these three helpers with CODE_ROOT; do not add a parallel pin comparer).

- Cost: the intent as written invites a fifth spelling of the owner/repo + fleet-membership check. `factory_config.repo_entry` already refuses malformed and unlisted names with a named FleetError (non-string or unmatched falls through to "repository not in fleet"), so a new regex is not needed for refusal; if one is added it must match `_REPOSITORY`'s anchors (it excludes `.`/`..` names) or the two drift.

- Disposition: fold-in (T-01 intent: use `has_repository_binding` for the bound-vs-unbound decision and `load_fleet` + `repo_entry` + `workspace_path` for resolution; no new regex, or import `_REPOSITORY`).
