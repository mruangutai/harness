## Finding

### F-SEC-C4-01 — T-04's nested governed lead is excluded from its cross-persona oracle (`med`, must-fix)

`tests/manual/probe-inflight-claim-lifecycle.py:393-450` collects `governed` solely with `started("harness-orchestrator", mark)`. `batch_plain_ids` correctly excludes every `harness-*` child, so the nested `harness-eng-lead` is not plain either. `observed_ids` can nevertheless discover `Nest.Probe` from sampled claims, which lets the lineage assertion pass. But `crossed_rows` checks persona only when an id is in the two-orchestrator `governed` list; it never validates a row for the nested lead id, and `every governed child settled` likewise covers only those two orchestrators.

Concrete failure scenario: a regression binds sampled id `Nest.Probe` to `harness-qa` (or another governed persona) rather than `harness-eng-lead`. The id still contains `.`, is not in `plain_ids`, is not one of the two direct orchestrator ids, and the parent orchestrators can settle. All six S3 checks can therefore print PASS while the claimed “no row ... crossed personas” property is false. A reviewer accepts SC-07 despite a claim/persona crossing that could authorize the nested run under another persona's domain.

Owner: **T-04**. Fix the oracle by deriving all governed `(id, expected persona)` pairs from lifecycle starts (including the nested lead), checking every sampled row for exact persona agreement, and settlement-checking every governed id. The final receipt must be regenerated by the operator; this review did not rerun the credentialled probe.

## Production wake-path audit and dismissals

- `.omp/extensions/harness-hooks.ts:910-985,1339-1345`: `openRun` first sets the shared gate unready, performs the exact-id `run-start`, and only then makes it ready. `agent_end` resets the gate even when the turn has no final text/yield. IRC wake's `agent_start` therefore reclaims before writes; a failed reclaim remains held and `tool_call` refuses writes. Unit coverage drives `agent_start` without a second `before_agent_start`, proves the exact id returns, and separately proves writes remain held before reclaim (`tests/unit/omp-hooks.test.ts:1895-1930`). - Probe corrections are otherwise sound: S2 samples only after wake; RPC waits for `get_state.isStreaming == false` and submits with `streamingBehavior: followUp`; S3 dispatches a permitted `harness-eng-lead` with a lead-shaped digest; plain ids exclude `harness-*`; lineage is obtained from sampled claims rather than pretending Main receives nested lifecycle. The defect is the missing persona assertion for that sampled nested identity.
- Credential-shaped canonical-diff scan found only the probe's environment-variable lookup for `<PROVIDER>_API_KEY`; it neither prints nor reads the secret value. No new dependency, URL, redirect, spreadsheet output, SQL/shell interpolation, PII disclosure, or committed credential was found.
