# Observations - harness-qa

- 2026-09-01: BUG-1128 c2 — `PLAN_MERGE_BIN` env var (test-plan-merge.py:24) lets the whole suite run against a mutant CLI without touching the tracked file; sibling imports (factory_config, harness_merge, harness_yaml...) resolve automatically if `PYTHONPATH` is set to the real bin/ dir, no need to copy them alongside the mutant.
- 2026-09-01: BUG-1128 c2 — a mutation probe written as a raw string-replace on source text (as case_amend_v3_identity_check_is_live does) can produce an UNBALANCED paren / SyntaxError mutant; the resulting "discrimination" is then just "does it crash", not a test of the logic it names. Always sanity-check a self-written mutant parses (py_compile or just run it once) before trusting its pass/fail as a semantic signal.
- 2026-09-01: bash-write-guard denies `cp`/redirect into any repo path outside an agent's domain, including inside a freshly created scratch git worktree — the "use a worktree" escape hatch (repo Expertise G-01/G-06) only helps when the write ALSO goes through the Write tool's own domain allowlist, which for qa is notes/observations paths only. For CLI-mutation testing, /tmp plus PYTHONPATH-pointed sibling imports is the only route that works end to end.
