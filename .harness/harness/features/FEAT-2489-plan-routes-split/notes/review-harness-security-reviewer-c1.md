## Finding

- **Substance · medium · T-01 / SC-03 — path containment.** `tests/integration/test-check-plan-routes.py:1927–1958,1965–1976` treats an inventory-controlled `plan` as a path for both I/O operations. `feature_corpus.py:327–344` selects the checkout or landed corpus but does not enforce containment. A relative path with parent components can resolve to an existing source file and produce a destination outside the fresh temp directory; `makedirs`/`copyfile` then create or overwrite files with the test runner’s permissions. A source symlink can also lead outside the selected corpus because `isfile` and `copyfile` follow it. An author who changes only the inventory can cause this when a maintainer runs the default suite on that checkout, provided the source is readable and the escaped destination is writable. A bad plan/task can be reported first without preventing the write: `check()` only records failure. This is a new write sink (absent at base), not a claim of arbitrary code execution or a production CLI overwrite. Must fix: validate a repository-relative path before either read; verify the resolved source stays within the authorized checkout/landed corpus and the destination stays within the scratch root before copying. Keep valid owner-root fallback and add regression checks for traversal and symlink rejection/no outside write.
