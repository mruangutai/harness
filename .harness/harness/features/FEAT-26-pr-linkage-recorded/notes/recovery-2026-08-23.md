## THE DEFECT THIS RECOVERY EXPOSED — issue #730, live in this plan

**T-02, T-03 and T-04 all write the SAME TWO FILES** — `gh-sync.py` and
`test-gh-sync.py` — and **T-03 and T-04 both declare `depends_on: [T-02]`**, so they are
concurrent with each other. The team runner dispatches both in one wave and they race on
two files.

This is exactly the class filed as **#730**: no gate checks that concurrently-ready tasks
share a `files:` entry. `check-plan-routes.py` reports 0 violations on this plan, because
nothing looks for it. It survived a plan round, a simplify pass, an architecture review and
a signature.

**The mitigation applied at the orchestrator level rather than by amending a signed plan:
dispatch T-03 and T-04 SERIALLY.** T-03 first, then T-04 after T-03's receipt lands. The
plan's DAG permits concurrency; nothing requires it. Amending `plan.yaml` to add a
`T-03 → T-04` edge would be the durable fix and belongs to pm, not to a recovery.
