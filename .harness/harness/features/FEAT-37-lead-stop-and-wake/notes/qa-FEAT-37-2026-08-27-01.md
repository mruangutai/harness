  resolved status (`active` or `excluded`-by-decision) in `harness.json`; nothing in DEC-187, DEC-35,
  or DEC-36 licenses treating incidental coverage under a different configured kind as resolving a
  distinct required kind. The matrix names kinds, not test files; `eval`'s box in the matrix stays
  unchecked regardless of how good the `unit`-kind coverage of the same file is. The ten deterministic
  assertions are real evidence of quality (and I re-ran them, all green) but they do not change
  `eval`'s configuration state.
- **FAIL vs ESCALATE.** The remedy is setting `eval.cmd`/`status` in `.harness/harness.json`. No
  task in T-01/T-02/T-04/T-05/T-06's declared `files:`/`surface:` list touches `harness.json` — it is
  `harness-dev-ops`'s domain (per DEC-187's own text: "`dev-ops` detects `test_kinds.cmd` per project
  at init"). Routing a fix cycle at a file nobody in this feature may edit only proves that. Hence
