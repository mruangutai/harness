## Findings

- **med — Current-turn confirmation is underspecified.** DESIGN.md, “Readback confirmed”, requires the latest user ID plus a “nonempty saved assistant”; plan.yaml T-06/T-07 repeat it. Neither requires that assistant to belong to the newly submitted turn. A second-turn GET containing the new user and only the prior assistant satisfies that literal predicate while losing the current reply [INFERENCE]. This contradicts BRIEF SC-02’s confirmed **exchange** and trusted answers’ real answer/persisted browser loop. Require the current assistant identity (or equivalent ordered current-turn association), not any assistant in the thread; assert prior successful exchange + new user persisted/current assistant missing stays incomplete, preserves draft, and never announces saved. Update DESIGN and both independently restated task contracts/QA assertions.
- **high — Recovery focus is unspecified and the prototype removes the triggering control.** DESIGN.md, “Composer and keyboard”, specifies send/composer focus but not focus after “Check saved messages”, “Retry restoration”, or “Renew local access”. Prototype index.html `checkSaved`, `restore`, and `renew` immediately call `setError(null)`; the error-dependent `action` is unmounted, with no recovery focus destination. A keyboard-focused recovery button consequently cannot preserve focus on that node [source-derived; not independently browser-exercised]. This leaves keyboard users without a stable continuation point. Specify a persistent recovery control during busy state or deliberate focus transfer on explicit activation, plus success/failure destinations without later stealing focus. Add keyboard-activated recovery assertions to T-02/T-07 and align the approval prototype. General “focus retention” language does not resolve this state flip.
- **low, advisory — Captured error reflow/theme coverage is incomplete.** rendered-evidence.json entries 05–08 are dark/1200px/16px; 09–11 are restored/non-error states. Thus light errors and error recovery at 320px/200% are not visually evidenced. DESIGN correctly requires them and honestly leaves light error rendering to future review; no measured contrast/reflow failure is alleged. Make T-02 browser fixture coverage explicitly include error panels/actions in both themes at 320px/200%, and inspect these during product UAT. Prototype capture expansion would improve pending operator review but is not itself a product pass.
