## End-to-end browser and transport contract

Browser surface: apps/web/src/features/chat/{chat-panel,thread-url}.tsx/.ts composed by app/page with layout/providers/globals. Before first send crypto.randomUUID becomes /?thread=<uuid>; this same URL recovers the single conversation across application restart. No localStorage message/credential authority or sidebar/history management. Missing/malformed/resource-mismatched thread is visible error, never silent new conversation.

Actual @ai-sdk/react useChat + ai DefaultChatTransport POST sends only newest user UIMessage and threadId. Server validates IDs/text-only input and injects its fixed resource/memory/options. @mastra/ai-sdk handleChatStream explicitly version:'v6' -> ai createUIMessageStreamResponse -> standard SSE x-vercel-ai-ui-message-stream:v1. SDK major v6 and wire header v1 are different identifiers. No parallel streamText/provider agent backend, AI Elements, deprecated toAISdkFormat or custom duplicate chat-state protocol.

GET verifies resource ownership before Memory recall({perPage:false}); convertMessages(dbMessages).to('AIV6.UI') preserves IDs and typed parts. DB-only composition never creates a model or requires ANTHROPIC_API_KEY; title generation, semantic/vector recall and model-backed working memory disabled. One bounded verified-TLS process/HMR pool/store/init owner. Stream completion/HTTP200 is not persistence success: SAME-thread GET must confirm the corresponding current user and CURRENT completed native SDK assistant IDs in current-turn order, with completed ordered persisted parts matching streamed output. A U1/A1/U2 readback without A2, old assistant/new-user-only, missing/unfinished/partial/mismatched identity/parts/order stays incomplete. Preserve visible streamed A2 and submitted draft; never adopt stale recall, clear draft or announce saved. GET-only recovery repeats the same predicate; renewal may bootstrap and resume GET but never replay generation. The former latest-user-plus-any-assistant predicate is rejected by c2 reader findings. Partial rendering is safe text, not executable model UI.

## D-02 local access decision

No account tradeoff is unresolved: browser access deliberately trusts the local machine operator, not account identity (#2) or production authorization. Bind only HTTP127.0.0.1. POST session bootstrap requires actual exact Host/listener port, matching Origin, Sec-Fetch-Site:same-origin and JSON/empty destination; forwarded-host tricks/cross-origin/same-site access rejected before provider/DB. Random nonce+issued/expiry HMAC-SHA256 signed privately with KAYA_API_STUB_TOKEN; eight-hour HttpOnly SameSite=Strict cookie kaya-local-session, Path=/api/platform, no Domain. Secure=false is explicitly restricted to loopback HTTP, not a deployment policy; SameSite alone does not isolate ports. Server token is NEVER in client JS/public env/body. Cookie credentials necessarily reach the browser's HttpOnly cookie jar, not JavaScript.

Browser GET/POST require signed cookie and same-origin Fetch-Metadata, POST exact Origin and GET matching Origin when supplied. CLI requires exact loopback Host and private bearer without browser metadata; bearer cannot bypass browser-origin guards. Same token survives application restart; rotation invalidates cookies. Expired cookie can visibly renew bootstrap, never automatically replay generation. Auth reads token only, readback DB only, send provider as well. This is a bounded local anti-cross-origin boundary, not protection from malicious processes/users already controlling the machine.

Sources: [Next cookies](https://nextjs.org/docs/app/api-reference/functions/cookies) documents async cookies and writes only in RouteHandlers/server functions before streaming; [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) documents HttpOnly fetch inclusion, host-only/no Domain and SameSite; [MDN Sec-Fetch-Site](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-Fetch-Site) documents forbidden browser header and same-origin vs same-site. These are researched vendor semantics, not exercised security tests.
