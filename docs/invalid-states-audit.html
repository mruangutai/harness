F1

feature.json has five concurrent writers and no lock

Silent

gh-sync.py:504, :531, :556, :624 — plus the orchestrator's own Edit tool

cmd_ship calls _record_pr then _record_status — two separate whole-document read-modify-writes. An orchestrator appending a run entry between them is erased: the second write read the document before the append and puts its own copy back. Exit 0, nothing printed. The inverse silently reverts pr to null, which is the exact decay FEAT-26 was built to stop.

Shape Route all four through harness_merge.locked_update — lock, read, transform, atomic rename, in one transaction. Its four existing callers prove the seam. Making runs[] appends a subcommand closes the orchestrator's unlockable path too.

F2

A task's status is an unvalidated bare string

Silent

harness_yaml.py:286 — status is not even a required field, and load_plan never validates it

Write status: Done with a capital D. derive_station's all(s == "done") is False, so the parent card never moves to Review. _EXPECT.get("Done") returns None, so the board comparison continues and that card is never checked. A feature whose plan says done, whose board says Building, and whose checker reports clean.

Shape One TaskStatus enum in harness_yaml.py beside the existing LEGAL_EXECUTION_MODES, validated in load_plan — which every runtime reader already goes through. Then delete the duplicate list in check-plan-routes.py and make _EXPECT total, so .get cannot return None.

F3

Two parallel collections keyed the same way, already drifted

Silent

gh-sync.py:431, :756, :776 — github.attached (list) beside github.issues (dict)

Two features on disk are drifted right now: FEAT-08 has 12 issues and 0 attached, FEAT-12 has 14 and 0. Nothing checks the relation — attached has zero grep hits in the state checker, the board auditor, or the schema validator. With T-05 in attached but not in issues, the code creates a fresh sub-issue then continues past attaching it. Orphan sub-issue, exit 0, every checker clean.

Shape Collapse to one map — issues: {T-NN: {number, attached}} — so "attached but unmirrored" cannot be written. Cheaper interim: make it a set and add one invariant asserting attached ⊆ issues.

F4

A count stored beside the thing it counts, hand-patched twice

Mixed

feature_schema.py:170-219 — a 34-entry map of feature → integer exemption count

The map was generated by scanning one working tree, so a feature whose record lives only on its branch defaulted to zero and its first run entry became unsatisfiable — FEAT-32 hit this minutes into its build. Deleting any legacy entry shifts every index after it. The file documents its own three failure modes, and two have already fired. Its own comment reads: read #718 before adding a third hand-written line.

Shape Put the flag in the data, not in a parallel count. The honest form is a predicate on the entry itself — require the field only when the entry carries a marker the current writer always emits, or only when the entry is not already on origin/main. Either way the exemption stops being an integer that must track a list's length.

F5

A tagged union whose tag is a string and whose payload is an open dict

Silent

board_lifecycle.py:268 — six kinds, three uncoupled consumers at :928, :933, :960

Add a seventh finding class, spelled right in the fixer and omitted from the fixable set. The dry run prints cannot fix, needs a human for something the tool can fix, and --apply never attempts it. The mirror case falls off the end of the fixer, writes nothing, and the re-audit reports the finding surviving a fix never attempted.

Shape One frozen dataclass per class with fix() as a method — and no method for the classes that have no fix. Then "fixable" is hasattr(f, "fix"), three sets collapse to one, and a wrong key becomes a type error rather than a KeyError inside a broad handler. No on-disk format changes; the type never leaves the process.

F6

change_type has no authoritative definition anywhere

Silent

harness.json test_matrix (10 keys, read by no code) · gh-sync.py:94 · validate-digest.py:158

Three partial copies, and two of them contain values the matrix does not (infra, ci). Mistype bugfix as bugfx: the label lookup returns None for both branches, so the issue is created with no bug label, silently. The matrix declares itself a floor, not a ceiling, so a missing row reads as "no required kinds" rather than an error. The bugfix ships with its test requirement never applied.

Shape A CHANGE_TYPES frozenset validated in load_plan, generated from the matrix keys so the two cannot disagree — the matrix is per-project, so hardcoding is wrong. The other two sets become subsets asserted at import, which surfaces the infra/ci gap immediately. That is the point.

F7

parent_origin is a sentinel string with no schema enum

Silent

feature-schema.json:76 and :101 — type ["string","null"], no enum · four copies of the two-value set

A merge or hand-edit writes "Created". The schema accepts any string. The reader silently coerces it to None. abandon then takes the else branch and prints parent #675 left open (origin=none) — leaving an issue this harness created open forever, and reporting a state the file does not contain. The coercion is the silent step: a value the schema allowed becomes indistinguishable from absence.

Shape "enum": ["created","adopted",null] in both schema locations, and one shared tuple instead of four copies. The schema is already validated at write time, so this becomes a blocking refusal for free.

F8

A committed foreign key into a gitignored tree

Signal loss

F9

In-flight claims have no identity, so release pops the oldest

Silent

inflight_registry.py:182, :209 — a claim is three fields and no id

Two leads each dispatch the same specialist. The second one's child returns first, and release removes the first lead's claim. Now the first lead has no live children recorded, so the refusal that stops a lead reporting a verdict about a child still running does not fire — silently. Meanwhile the second lead is falsely blocked, with a refusal naming a start time and a dispatcher that are not its child's. One persona being single-flight is all that keeps the window narrow today.

Shape claim() returns an opaque token stored in the claim, and release() takes it — removing that claim or reporting it already gone. Keying on dispatcher plus working directory is cheaper but not unique.

F11

One flag is dead on 102 of 118 entries; the other revokes a write grant

Silent

harness_yaml.py:380 — the only line reading either flag · team-config.yaml, 118 domain entries

Write upsert: false intending read-only: the flag is never read, the entry lands in the writable set, and full write is granted — a denial the author believes exists does not exist. Add read: true to an existing writable entry meaning "also readable": the entry is dropped and the write grant is revoked, with the eventual denial pointing at a path rather than at the flag that caused it.

Shape One required tagged field — access: write | read — raising on any other value or on absence, so every ambiguous combination becomes unrepresentable. Cheaper interim: raise when both flags appear together, and raise on upsert: false. Two lines, and both silent cases become loud.

F13

review_sha has four live shapes, and one is not a SHA

Silent

feature-schema.json:53 — plain string · check-state.sh:224 only asks whether it is empty or a placeholder

Measured across 34 features: 9 full SHAs, 21 abbreviations, 3 "none" strings, and one SHA range — a606d7a..9b07cfc. Nothing resolves the value against git. One character off reports as pinned, and the reviewer either gets fatal: bad object or, worse, a different real commit — a review pinned to a tree nobody built. F14

4.17 seconds for one plan, mostly re-parsing one unchanged file

Cost

check-plan-routes.py:61-83 — one subprocess per declared path, no memoisation anywhere

Each resolution spawns a subprocess that re-parses the 318-line team manifest 19 times — once per name, 23 ms — for a total of 96 ms per call. One in-flight plan declares 53 paths. Measured end to end: 4.17 s, with 33 of 34 features skipped as shipped. Across all 24 plans that is 524 paths, and the design explicitly allows several concurrent flows.

Shape Two one-liners: cache the loader keyed by path and mtime, and memoise the resolver by path. The structural fix is a batch mode taking paths on stdin, turning 53 subprocesses into one and 4.17 s into roughly 0.1 s.

F15

Every feature record is parsed seven times per run

Cost

check-state.sh:177, :573, :708, :914, :953, :1063, :1278 — seven independent glob-and-parse passes

At 34 features that is 238 opens and 238 parses of documents that cannot change during the run, plus one record read a second time inside a loop that already parsed it, plus a fleet file loaded inside a per-feature loop. Seconds today, but linear in feature count with a 7× constant — and the project reached 34 features in four weeks. Two invariants can also disagree because a file changed mid-run.

The agents that write and review this code

Measured by grep across every engineer definition and every skill they preload: no rule that reaches any of the five engineers mentions performance, complexity, data structure choice, or input size. The code reviewer has no instruction about any of them either.

A1

Give the reviewer four named shapes, enforced by the hook

The security reviewer has an enumerable vocabulary, so you can ask it whether it covered injection. The code reviewer works from judgement — it finds real defects and nobody can say what it did not look at. Four shapes, each with a measured instance in this tree: one thing with two record shapes (F7's neighbour), absence spelled as a value (F7, F13), a matcher whose shape cannot reach what it seeks (eleven instances in three days), and a test double answering what the real system would refuse.

The detail that makes it a gate rather than a ritual: set-valued schema entries get exact membership checks, while list-valued ones get a type check only — no row validation anywhere in the validator. So it must be four enum scalars. A list field would let an empty list pass the hook while asserting nothing.

A2

The two sentinel strings are the same shape, already live

F7 and F13 are one finding wearing two names: absence spelled inside the domain of real values. Both fix with a schema line, both are already enforced at write time, and both are currently causing damage — an issue left open forever, and 25 of 34 features carrying a review pin that nothing resolves.

A3

One row in the rationalization table

All five engineers already load the skill that carries this table, and the table exists to kill rationalizations. One line, and it is the defect that cost four live API runs.

A4

Require the input size, never the optimization

"Always reach for the better structure" collides with this project's own rule that structure is earned by a real bottleneck and never designed in anticipation of one. That instruction produces a hash map over five known rows plus a cache with an invalidation bug — debt manufactured by the rule meant to prevent it.

What separates a principal engineer here is knowing N and saying which term binds. So a required scale: field in the shared engineer digest, where unbounded is a finding rather than an answer. One engineer definition already carries exactly this sentence about data volume; the work is generalizing it, not importing it.

A5

The chain is closed at the planning layer, not the engineer

Two planning skills use "performance is good" as the canonical example of a bad criterion — correctly — but neither shows a falsifiable one. So omitting performance is the compliant path. Then no change type requires performance evidence, so the gate cannot ask, so the dispatch does not carry it. And the reviewer's first stage treats unrequested optimization as scope creep, a finding even when it is an improvement.

An engineer told to optimize without fixing the brief layer first is being put in conflict with a review gate. Give the planner the falsifiable form — a bound and the input it was measured on — before asking anyone downstream to honour it.

Before any of this is written

Four of these findings land in the layer that does the checking — the state checker, the digest validator, and the schema the domain guard enforces. This project's own rule is that it plans changes to its enforcement layer and never executes them through the team, for the stated reason that the artifact under change is the artifact doing the checking. So A1's teeth, F8, and both sentinel fixes route through a brief and a signature, not a dispatch.

The two that are free of it are the rationalization row and the input-size field. The rationalization row is one line, and it is the one that would have caught the defect four live API calls had to find instead.
